## 🎯 The 10 YAML Schema Types

### State Schemas (4 types) - Internal Use
Located in `knowledge/.state/` as pure YAML files

1. **task_state** - Runtime task execution
   - Fields: id, topic_id, scheduled_start/end, actual_start/end, status, priority, task_type
   - Used by: TacticalTimeline, TaskCard
   
2. **progress_state** - Per-topic mastery
   - Fields: topic_id, mastery_level, confidence, concepts_mastered, trend, study_count
   - Used by: TacticalMasteryGrid, ProgressStateViewer
   
3. **goal_state** - Long-term objectives
   - Fields: goal_id, category, target_completion, current_progress, milestones, urgency
   - Used by: TacticalDashboard, MemoryBase
   
4. **session_state** - Study session logs
   - Fields: session_id, start/end_time, duration_min, tasks_completed, quality
   - Used by: SessionStateViewer, time bank

### Knowledge Content Schemas (6 types) - Notebook LM Friendly
Located in content directories as Markdown with YAML frontmatter

5. **quiz_result** - Assessment outcomes
   - Fields: topic, date, questions_correct/total, progress_before/after, identified_gaps
   - Generated by: Notebook LM
   - Transforms to: progress_state
   
6. **study_plan** - Structured schedules
   - Fields: date, focus_topics, total_time_min, priority
   - Generated by: Notebook LM
   - Transforms to: task_state (multiple)
   
7. **focus_recommendation** - AI suggestions
   - Fields: date, time_available_min, priority_topics, reasoning
   - Generated by: Notebook LM
   - Transforms to: study_plan
   
8. **progress_update** - Session summaries
   - Fields: topic, date, progress_before/after, time_spent_min, concepts_mastered
   - Generated by: Notebook LM
   - Transforms to: progress_state
   
9. **task** - Scheduled tasks (legacy)
   - Fields: title, dateKey, start/end, taskType, tags, status, progress
   - Existing format
   - Transforms to: task_state
   
10. **goal** - Long-term objectives (legacy)
    - Fields: title, category, deadline, status, topics
    - Existing format
    - Transforms to: goal_state

## 🔄 Data Flow Architecture

```
External Input (Notebook LM / Manual)
         ↓
   YAML Parser (validate & detect)
         ↓
    Type Detection
    ↙          ↘
Transform?   Store Direct
   ↓            ↓
Transformer   useStore
   ↓            ↓
   useStore ←─────┘
        ↓
   UI Components
   (Dashboard, Timeline, Mastery)
```

### Transformation Matrix

| From Type | To Type | Function | Purpose |
|-----------|---------|----------|---------|
| quiz_result | progress_state | quizResultToProgressState | Update mastery from quiz |
| progress_update | progress_state | progressUpdateToProgressState | Update mastery from session |
| study_plan | task_state[] | studyPlanToTaskStates | Generate scheduled tasks |
| focus_recommendation | study_plan | focusRecommendationToStudyPlan | Convert recommendation to plan |
| session_state | progress_update | sessionStateToProgressUpdate | Create session summary |
| task | task_state | taskToTaskState | Legacy format migration |
| goal | goal_state | goalToGoalState | Legacy format migration |
| progress_state | goal_state | aggregateProgressToGoal | Update goal progress |

## 📊 Complete Usage Examples

### Example 1: Quiz-Based Learning
```
1. Notebook LM: "Quiz me on NMCP Module 1"
   → Generates quiz_result YAML
   
2. Import to OVERRUN
   → Validates schema
   → Transforms to progress_state
   → Updates mastery: 50% → 75%
   
3. TacticalMasteryGrid updates
   → Shows new mastery level
   → Displays identified gaps
   → Suggests next focus
```

### Example 2: Study Plan Generation
```
1. Notebook LM: "Create study plan for tomorrow"
   → Generates study_plan YAML
   
2. Import to OVERRUN
   → Validates schema
   → Transforms to task_state entries
   → Creates scheduled tasks
   
3. TacticalTimeline updates
   → Shows new tasks on timeline
   → Displays time allocations
   → Enables status tracking
```

### Example 3: Goal-Oriented Planning
```
1. Create goal: "NMCP Exam Sept 2024"
   → Creates goal_state
   
2. Notebook LM generates study plan
   → 3-week schedule
   → Transforms to 30+ task_state entries
   
3. Execute daily tasks
   → Update task_state status
   → Aggregate progress to goal_state
   
4. Complete goal
   → All milestones achieved
   → Goal status: active → completed
```
